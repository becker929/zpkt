# ears: measure a render

`ears` takes an audio file and says what is in it, as numbers: loudness, true peak, energy per
band, spectral shape, an embedding, and how far it sits from your own reference tracks. It is
what an agent uses instead of listening, and what I use to check that a render is what I think
it is.

```bash
uv run ears analyze take.wav                 # the profile, as a table
uv run ears analyze take.wav --json          # the full AudioProfile
uv run ears compare v1.wav v2.wav            # loudness and centroid deltas, embedding similarity
uv run ears corpus build ~/Music/references  # measure your reference tracks once
uv run ears corpus distance take.wav         # where a render sits among them
```

## What it measures

| Group | Measures | Notes |
|---|---|---|
| Loudness | integrated, short-term peak and momentary max (LUFS); true peak (dBTP) | Measured on the file's real channels. True peak is 4x oversampled, not the sample peak. |
| Bands | share of energy in sub, low, mid, high, air | Shares sum to 1. |
| Spectral | centroid, rolloff, bandwidth, flatness, onset strength, MFCCs, chroma, key | librosa. |
| Embedding | a 512-dimension DCLAP vector | Needs the model (below). `null` without it, never zeros. |
| Rhythm, pitch | beats and tempo (`--rhythm`), notes (`--pitch`) | Optional; each needs an extra package (madmom, basic-pitch). |

A dual-mono stereo file reads about 3 LU louder than the same signal as one channel. That is
BS.1770, not a bug.

Anything that fails is listed in the profile's `errors`, and the rest is still returned.

## Your reference corpus

A corpus is a folder of tracks you want yours to sit among. No audio or measurements ship with
ears; you bring the folder.

```bash
uv run ears corpus build ~/Music/references           # writes ~/.cache/zpkt/corpus.json
uv run ears corpus distance take.wav
```

```
take.wav against 4 corpus tracks
 Measure                   Yours    Median       p10       p90     z
 lufs_integrated           -14.1     -6.04     -7.13     -4.64  -7.0
 true_peak_db             0.0644    -0.303    -0.805    -0.161  +1.5
 band_sub                  0.828     0.785     0.706     0.892  +0.4
 band_mid                 0.0507    0.0866      0.06     0.101  -1.5
 ...
Embedding: 0.963 to the corpus centre (corpus tracks: median 0.959, 10th percentile 0.954)
  0.958  Remon Verhoeve - Patriotic.wav
```

Each row is one measure: your render, the corpus median, its 10th and 90th percentiles, and `z`,
the number of corpus standard deviations from the corpus mean. Rows outside the 10th to 90th
percentile are highlighted. The embedding lines say how close the render is to the centre of the
corpus compared with the corpus's own tracks, and name the nearest ones.

`--out` and `--corpus` choose another file; `EARS_CORPUS` sets the default. Use several corpora
for several targets (a genre, a label, your own releases). With four tracks the percentiles mean
little; a few dozen is where the ranges start to say something.

## The embedding model

Embeddings use DCLAP from
[AudioMuse-AI-DCLAP](https://github.com/NeptuneHub/AudioMuse-AI-DCLAP) (AGPL-3.0), a distilled
CLAP. It is 22 MB and is not in this repo.

```bash
scripts/fetch_model.sh       # downloads to ~/.cache/zpkt/models/dclap and checks the hashes
```

ears looks there by default; `EARS_DCLAP_MODEL` points it at another copy. Everything except
embeddings works without the model.

## mlab: mastering meters

[`mlab/`](mlab/) is a second, stricter set of instruments for the last steps of a track. Every
meter is checked against a signal whose answer is known before it is trusted.

```bash
cd mlab
uv run mlab calibrate                  # 99 known-answer checks -> calibration/CALIBRATION.md
uv run mlab measure take.wav           # the full measurement sheet
uv run mlab premaster take.wav         # a premaster checklist
uv run mlab deliver take.wav           # platform normalisation and a codec round trip
uv run mlab refs take.wav refs/        # against a folder of references
uv run mlab hyp run hypotheses/H001-loudness-buys-nothing-on-youtube.yaml
```

It was built while mastering one track, HW002, and its guides, hypotheses and reports are kept
as written: start at [`mlab/INDEX.md`](mlab/INDEX.md).

## Modules

| Module | Does |
|---|---|
| `analyzer.py` | An audio path to an `AudioProfile`; runs the extractors side by side. |
| `loudness.py` | LUFS, true peak, band energy. |
| `features.py` | Spectral features. |
| `embeddings.py` | The DCLAP embedding. |
| `corpus.py` | `build`, `save`, `load`, `distance`. |
| `similarity.py` | Pairwise comparison of two profiles. |
| `models.py` | `AudioProfile` and its parts; the source of `lib/contracts/audio-profile.schema.json`. |

ears imports nothing from `hands`. It consumes audio files and produces JSON; the schema is
generated by `scripts/gen_schema.py`, and a test fails if the committed one is stale.

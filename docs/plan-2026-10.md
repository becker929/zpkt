## Phase 2: the voice production loop

Turn-based, so the mic and the speaker are never on together, and the car's Bluetooth stays in its media
profile.

- **One turn:**
  1. You listen to an A/B that switches every **1 bar**, loudness-matched.
  2. You talk, and end with the stop word **"tomato"**.
  3. Claude works, narrated.
  4. The new A/B plays.
- **No separate agent.** It is a normal Claude Code session, started in zpkt, with a voice interface and skills
  and scripts that keep growing.

Steps:

- **V1, speech on the Mac and measurement.** V1 can start alongside Phase 1.
  - During a turn, the page streams mic audio to the Mac.
  - A local speech-to-text model, chosen by benchmark on the Mac, transcribes it and spots "tomato".
  - Every stage is timed: mic open, first word, stop word, first narration, plan, render start and end, cache
    hit, first A/B bar. Compare first versus later turns, Safari versus Chrome, and Bluetooth versus the phone
    speaker.
  - Confirm whether Claude accepts streamed audio input.
- **V2, the bridge.**
  - One long-lived Claude Code session. Each spoken turn becomes a message.
  - Replies are spoken.
  - A Haiku side model turns tool activity into short narration: rate-limited, with stale lines dropped.
- **V3, the skills.**
  - `render-plan`: plan JSON to knobs set in the open set, then one short exported loop.
  - `ab-1bar`.
  - `plan-cache`: keyed by the base set's version plus the canonical plan, with nearest-neighbour search over
    range-normalised knob values. A close match plays at once while the exact plan renders.
  - Write-ahead: render the likely next plans (more, less, undo, the other end) while you listen.
- **V4, the turn page.** Listen, then talk, then narration while Claude works, then the new A/B.
